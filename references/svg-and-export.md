# 独立 SVG、连线与导出规范

## 内嵌复用图标

1. 读取候选 SVG，确认 `viewBox`、实际图形边界，以及是否含有 `<defs>`、样式、渐变、遮罩、裁切、字体或图像引用。
2. 将图标图元复制进目标 SVG 的 `<g>`，或建立内嵌 `<symbol>` 并以同文件 `<use href="#…">` 引用。需要最大化逐元素编辑兼容性时，优先展开为 `<g>`。
3. 复制被使用的定义，给**每个图标实例**中的 ID 增加唯一前缀，例如 `input_database_`。同步重写 `href`、`xlink:href`、`url(#…)`、样式选择器及其他 ID 引用，避免渐变、裁切和遮罩串用。
4. 隔离图标样式。原始 `.st0`、`path { … }` 等规则不能污染整图；优先转换成明确的图元属性，或为选择器加作用域。将 `currentColor` 解析为显式颜色以改善编辑器一致性。
5. 使用等比变换放入占位框，处理非零 `viewBox` 原点；不要独立拉伸宽高。根据实际轮廓做视觉居中，必要时微调统一描边尺度。
6. 检查颜色替换没有破坏镂空、透明度、双色语义与 `fill="none"`。不要无差别替换全部 `fill` 或 `stroke`。

相同 `viewBox` 和占位尺寸不等于相同可见尺寸。对明显偏小、偏移的图标，使用矢量工具的实际边界，或透明背景渲染的 alpha 边界辅助计算缩放和平移；保持原始 path 为矢量，不把测量用位图放回主图。考虑描边及滤镜范围，不能裁掉真实内容。先统一可见外框，再根据笔画粗细和视觉重量小幅调整，不强求每个图标像素面积相同。

图标导入器要声明支持范围。对已确认仅包含 path 的单色图标可以采用简单复制与指定颜色替换；遇到样式、渐变或嵌套引用时，应完整处理或明确报出不支持，不能悄悄丢弃它们。

禁止依赖 `<image href="icons/foo.svg">`、`<use href="other.svg#icon">`、`file://`、绝对磁盘路径、远程字体、CSS `@import` 或其他外部资源。SVG 命名空间 URI 是标识符，不是需要下载的资源，不能误删。

保持图标为矢量。确需包含用户提供的照片等位图时，将图像内容以内嵌 data URI 保存，说明该部分不具备逐图元编辑能力；不要用位图替代可用的矢量图标。

## 可编辑性与字体

- 根元素声明 SVG 命名空间，提供合理的 `viewBox` 与明确尺寸。
- 默认使用基本路径、矩形、圆、折线、文本与分组；避免依赖脚本、动画、`foreignObject` 或编辑器私有功能。
- 保存为 UTF-8，正确转义文本特殊字符。长标签显式用 `<tspan>` 换行，不依赖浏览器自动排版。
- 使用本机已验证可渲染的字体及回退字体；中文标签必须检查字形支持。最终图不引用本地字体文件。
- 独立 SVG 不代表各机器字体必然相同。保留文字的主 SVG 方便编辑；若交付必须严格保持字形，可另外输出文字转路径的副本并清楚命名。不可用转路径副本替代可编辑文本主文件而不说明。
- 若采用嵌入字体，先确认许可和目标渲染器支持，并在实际导出结果中验证。

## 连线与边界

框内居中按 [组合内容居中](visual-craft.md#组合内容居中) 执行。把单元素或图文组合放进独立 `<g>`；字体加载完成后测量所有可见内容，统一到同一坐标系，取其联合包围盒 `B=(bx,by,bw,bh)`。对预先确定的内容区 `C=(cx,cy,cw,ch)`，整体平移 `dx=cx+cw/2-bx-bw/2`、`dy=cy+ch/2-by-bh/2`。不把背景、透明占位框或外接连线纳入内容包围盒；不以逐个元素分别居中代替组合居中。

`text-anchor="middle"` 只处理文字的水平锚点，`dominant-baseline` 也不能单独证明多行文字和图标组合垂直居中。浏览器文本框是字体边界近似，必要时用矢量字形边界或透明渲染辅助检查可见轮廓；测量后重新渲染并查看上下、左右留白。换字体、换行、替换图标或改变框尺寸后重测。局部坐标含缩放/旋转时将平移量转换回局部坐标，不能直接套根坐标数值。移动含内部关系的组合时一起移动内部连线，并重算外接端口。

- 将布局参数作为唯一坐标来源，按容器位置计算连接锚点；调整节点后重新计算连线。
- 连接线可在容器之前绘制，以降低穿入节点时的视觉干扰，但端点仍须真正落在正确边界，不能靠遮挡掩盖错误路线。
- 简单连线优先直线或少量直角转折；使用一致的 `stroke-linecap`、`stroke-linejoin` 和转弯方式。双向关系仅在语义需要时使用双箭头。
- SVG 箭头使用统一的 `<marker>`；设置 `viewBox`、`refX/refY`、`markerWidth/Height`、`markerUnits` 和 `orient`，使尖端与路径终点对应。检查箭头是否被 marker 视口或画布裁切。
- 分支在真正的共同坐标处接合；需要表达连接时可用小节点标记。优先重新布线减少交叉。
- 边框和路径的几何坐标不包含全部视觉范围。额外计入半个描边宽度、箭头大小及滤镜范围；文字以渲染后的字形检查。
- 文字与图标使用各自的占位框，留出内边距；连线通道不得穿过这些占位框。不能用裁切容器来隐藏内容溢出。

## 结构检查

使用 XML 解析器检查 SVG 语法，并检查：

- 每个 ID 唯一，所有本地片段引用都指向存在的 ID。
- `href`、`xlink:href`、样式中的 `url(…)`、`@import`、外部样式表以及字体引用不存在外部依赖。
- 不包含非必要的脚本、事件处理器或外部实体声明。
- 主文件包含真实可编辑图元，而非仅有一张覆盖画布的位图。

检查 `<defs>` 和内嵌图标内部，不能只检查 SVG 顶层。正则检索适合辅助发现疑点，不能单独证明复杂 SVG 自包含。结构检查也不能证明无重叠或可读性，必须配合渲染检查。

随 skill 提供的检查器使用 Python 标准库：

```bash
python3 <skill目录>/scripts/check_svg.py figure.svg --output structure-check.json
```

它检查 XML、画布、重复 ID、片段引用、常见外部依赖和动态内容，并输出 JSON。退出码 `0/1/2` 分别表示支持范围内通过 / 发现错误 / 需要额外检查。样式表、转义 CSS、未支持图元等会进入待检查列表；该脚本不是完整 CSS 解析器，也不是安全净化器。遇到待检查项应使用合适的解析器或人工核验，不删除检查记录来制造“通过”。

几何辅助检查使用实际字体加载完成后的包围盒。浏览器中，`getBBox()` 与 `getBoundingClientRect()` 的坐标系不同；先统一变换和单位，再比较容器内框。检查子元素时排除容器背景本身，另行检查路径、marker、描边和标签间距。文字在容器内不代表它没有压住其他元素。

## 导出与视觉复查

可选工具链的完整分工、依赖查找、Python绘制示例、Sharp与浏览器脚本命令，以及Pillow/Poppler/pypdf检查用法，见 [工具链用法](toolchain.md)。本节规定各工具路径共同遵守的导出质量要求。

先探测环境已有 SVG 渲染工具，选择实际可用且支持图中功能的工具。可使用 Inkscape CLI，或现有的 CairoSVG、resvg、浏览器等路径；不同工具的字体、marker、滤镜支持可能不同，需验证结果。

命令不在 PATH 中不代表整个环境无法渲染。检查用户指定工具、项目依赖及环境提供的能力清单；也可显式配置解释器、包目录或渲染器路径。任何宿主应用的依赖查找接口都只是可选便利，不能成为流程前提。不要假设某个包或浏览器已安装，不搜索固定的私人缓存路径。

例如，环境中已有 Inkscape 时可运行：

```bash
inkscape figure.svg --export-area-page --export-type=png --export-filename=figure.png --export-width=2400
inkscape figure.svg --export-area-page --export-type=pdf --export-filename=figure.pdf
```

使用实际工作路径，执行前确认工具可用。不要将示例命令执行成功当作视觉验收。导出页面边界应与 SVG 画布一致；若需要紧裁切，明确记录并让各格式保持一致。

- PNG 按最终使用尺寸计算像素：`像素宽 = 宽度(mm) / 25.4 × DPI`。用户未指定时可按 300 DPI 起步；期刊另有要求时遵从。只改 DPI 元数据不会增加细节。
- 像素尺寸与 DPI 元数据分别核对；渲染器可能在输出时移除密度信息。若 PNG 需携带物理尺寸，明确写入正确密度。
- PDF 尽量保留路径与文本，核对页面物理尺寸、字体和箭头；避免无意将整页栅格化。
- 浏览器打印时，显式设置页面物理尺寸、零边距、打印背景并关闭页眉页脚；打印样式使 SVG 恰好匹配页面。检查单页、文字可提取、字体和图像对象。浏览器可能对页面尺寸取整，应读取实际 MediaBox 并记录误差；需要严格尺寸时修正后重新检查。
- 实际查看 PNG 整图及局部，并按论文最终显示尺寸判断文字和细线。PDF 导出后另行渲染页面检查。
- 如担心相对资源残留，将最终 SVG 单独复制到临时空目录再渲染；此检查用于补充引用检查，不能代替它（绝对路径依赖仍可能在本机可用）。
- 缺少工具时先寻找已有可行路径；确实无法渲染或导出时，交付已完成部分并准确注明未完成的格式和验证项。
