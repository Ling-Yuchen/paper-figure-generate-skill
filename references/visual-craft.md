# 论文图的视觉层级与细节设计

用于新绘框架图、重绘以及“缺少质感”“太像模板”“只有框和箭头”等反馈。规整网格解决秩序，本节解决网格内的信息主次、图形表达和做工。质感来自清楚的关系、合适的密度与一致的细节；纹理、阴影和更多颜色不是默认修复手段。

## 先判断问题，再选设计动作

先查看当前图与用户参考图，记录实际发现的可定位问题。用“所有分区底色同样重，核心机制没有视觉入口”替代“比较普通”，用“图标比方法内部图形更醒目”替代“不高级”。区分结构问题与表面问题：结构松散时回到分区规划；结构清楚但主次不分时调整视觉重量。

绘图说明中先回答：

1. **叙事任务**：此图要解释组成、运行机制、对照还是结果？读者第一眼应识别什么，接着沿什么关系阅读？
2. **观看尺度**：最终栏宽是多少？缩小后必须保留哪些区别？字号按物理尺寸确定，不能照搬网页或投屏字号。
3. **视觉方向**：从参考中提取可执行的规则，例如“中性外框、重点局部着色、同级标题在各自标题区居中”，而不只写“简洁专业”。
4. **内容容量**：各区应有多少必要的图文单元，哪些空间用于机制、哪些用于路由？用缩略线框估算，不靠填充装饰解决空洞。

已有参考和足够上下文时直接提出方案并执行，不将这些问题变成固定的用户审批表。缺失科学关系或用户明确要选择方向时，再询问真正影响结果的信息。

## 建立可复用的视觉参数

生成程序集中保存角色参数，例如 `ink / muted_ink / grouping_rule / node_rule / core_accent / core_tint / label_size / annotation_size / icon_extent / spacing_unit`。用角色引用数值，避免在各模块临时添加近似色和孤立坐标。参数服务于本图，没有一套必须使用的主题。

| 维度 | 设计决策 | 复查方式 |
| --- | --- | --- |
| 图形层级 | 主分区用底色和轮廓建立范围，子分区表达局部归属，功能节点提供接口；按作用分配边框强度 | 缩小或灰度查看，父子范围是否清楚、核心机制是否醒目 |
| 字体层级 | 标签、分区标题和注释按作用区分字重、位置及有限的字号变化 | 不看颜色也能区分标题与操作；最终尺寸可读 |
| 空间节奏 | 同级单元统一内边距和基线；层级之间用更大间距，连接占独立通道 | 检查图标—文字、标题—内容、节点—边的间距是否成体系 |
| 配色层级 | 每个色相表达一种已定义的类别；明度、面积和深浅建立主次 | 同一语义不随模块换色；不是每栏都需要大面积底色 |
| 图标层级 | 图标提示实体或操作，核心机制用专门的结构图形表达 | 遮住图标后机制仍可解释；遮住机制后不能只剩可互换的图标卡片 |

线宽由边界的作用决定，不预设“外框一定最细”。承担系统归属的主框可以比子框更明确；仅用于排版的分隔线可以更轻。结合颜色、面积、线宽判断总重量，不能同时把所有底色、边框和分隔都淡化。

## 底色、边框与子分区

先为本图选择一套容器层级，再给模块套用，避免每个框独立调色。下列是可调整的起点；没有对应语义的层级应省略。

| 层级 | 底色与边框 | 用途与限制 |
| --- | --- | --- |
| 画布 | 白色或接近白色的中性底，不必再包总边框 | 作为论文页面的一部分，外围背景不争夺注意力 |
| 主分区 | 能辨认的低饱和浅底 + 同色系中深边框；可配稍深的标题带 | 表达系统或阶段范围，让多个子单元被读成一个整体；浅底不等于肉眼无法区分的白 |
| 功能子分区 | 继承父区色系，通过不同明度的底板或次一级边框区分 | 包含确有归属的多个节点或一个复杂局部机制；不随意引入新色相 |
| 原子功能节点 | 常用白底 + 清楚的轮廓，或与父底明确可分的浅底 | 提供可编辑对象与连接端口，不再给每个图标套小卡片 |
| 核心或特殊节点 | 同色系更明显的局部填充、适量加重边框 | 强调有科学依据的重点；不与主区颜色争相抢眼 |
| 共享区 | 中性浅底 + 独立边界；内部可用分隔线 | 与各阶段区别开，读写归属清楚；不能因其辅助身份而弱到无法辨认 |

### 颜色按面组织

为每个需要分类的主区定义 `panel_fill / header_fill / panel_stroke / subgroup_fill / subgroup_stroke / node_fill / node_stroke`。同一级使用同一配色逻辑，色相区分类别，明度区分层级。不要让每个子框都换一个新色相，也不要在所有层级重复同一底色和同一条边。

例如一个绿灰处理区可以从主底 `#F1F6F2`、标题带 `#DCEAE1`、主边 `#608273`、子区底 `#E3EEE7`、子边 `#8DA697`、节点白底与 `#608273` 节点边开始。它只是色阶示例，不强制所有图都用绿色。邻接面颜色是否能区分，以实际渲染与灰度小样判断。

标题带可以强化主区识别，但必须有统一高度与基线；不是额外的独立卡片。每个界面只画一次分隔，避免标题底边与内容顶边叠成双线。填充、标题带及外框按正确图层组织，圆角处不露色，不靠白块遮盖错误。

### 线宽按物理尺寸校核

先用pt规定印刷线宽，再按本图比例换算为SVG单位。以180mm宽、1600单位画布为例，1 SVG单位约0.319pt，可试用：主分区2.4单位（0.77pt）、子区1.6单位（0.51pt）、节点2.0单位（0.64pt）、主要关系3.0单位（0.96pt），内部弱分隔1.2–1.6单位。缩小到另一栏宽后重新校核，不能照搬数值。

这些线宽不是强制顺序。重要的是同级一致、相邻层级可区分、关系线能沿全程追踪。边框加深时先考虑是否需要同时加粗；避免以极淡细线表示重要归属，也避免厚重暗框包住每一层。虚线只表达约定的逻辑类别，不当作“子框专用装饰”；不以虚线替代缺少的层级设计。

### 子框先有归属，再有形状

- 先在模块树中写清子分区包含谁、属于哪个父区。并行编码、运行时交互、候选生成与筛选等局部机制可形成子分区；视觉上相邻不代表逻辑上同属。
- 子分区应容纳自己的必要节点、内部连线和短标题。标题可统一置顶或置底，但必须预留标题区，不能压在线路或节点上。
- 选择能减少解释成本的划分。并行分支可在一个子框内分行；真正独立机制可并排分框；只是同一节点里的标签与图标无需再套框。
- 外层维持方正规整，内层依据方法变化。共享底板不要求所有内部单元大小一致，子框不必填满父框。
- 子框内边距按内容与路由计算，父子边框不要贴边或共线叠画。相邻子框之间留清楚通道，跨子区的边到达真实节点端口，不能止于子区外框。
- 在SVG中使用真实嵌套分组；背景先画，连接和内容按作用分层。新增底板后重新检查路径是否被遮住，不能只检查它没有盖住文字。

### 容器层级验收

分别查看彩色、灰度和最终栏宽：能否辨认主区范围、子区归属及功能节点；白色节点能否从浅色父底中分离；标题带、分隔和外框是否协调；有无重复描边、过粗边框或消失的细线。每个新增子框都能用模块树解释。若父子层次仍不清楚，应调整面与边的组合，不继续机械减淡或统一换色。

## 让方法机制成为视觉入口

本节用于以解释方法机制为阅读任务的图。比较图、分类图等按其内容组织对应项与差异，不为了建立视觉入口新增机制或强行突出某一方案。

选择一个与论文信息重点相符的区域投入最多细节：如融合运算、候选筛选、状态转移或训练目标。可通过更清楚的内部构造、更充裕的面积、局部低饱和强调和更直接的线路使其醒目。其他部分完整、准确地服务于它。包含多个同等重要机制时，采用清楚的局部层级，不强迫只剩一个重点。

- **输入和产物**可以是紧凑的符号与标签；不必重复“阶段框—卡片框—图标底板”三层容器。
- **功能节点**保留需要连接端口的可见边界。删除边框后，要把线接到明确的图元或接口；不能继续把箭头停在原来不可见的框边上。
- **方法内部机制**使用有来源的图形语法：并行条带进入融合、代表性候选与筛选路径、已知状态与转换等。图元的数量、颜色和连法都可能被解释为科学断言，必要时在图注标明示意，不虚构算法细节。
- **共享或辅助组件**压缩成有明确归属的带状区，降低其视觉重量；读写接口、标签与通道仍须完整。
- **边与条件**优先在接近发生位置的通道标注，主数据流与返回路径可用线型区分；读者不应绕图寻找条件的归属。

精致细节应帮助解读，例如融合节点中的两组输入保持到合并位置才汇合、重复符号准确对齐、箭头尖端与接口留白一致。避免靠虚构向量维数、概率、性能数字或装饰性刻度增加“技术感”。

## 图文做工

**字体看适合度，不看稀有度。** 优先论文或期刊的字型规范，其次选目标环境具备且字形清楚的字体。常见无衬线字体完全可以形成精良图版；不因追求风格强制下载展示字体。不照搬营销图中标题为正文数倍的比例。专业符号、上下标、大小写和缩写保持一致，多行标签显式换行。

**图标按可见轮廓归一。** 相同viewBox大小不意味着相同视觉体量；比较实际轮廓、墨色面积及留白，调节尺度和光学居中。单色图标尽量保持一致的填充/描边语言；不能把所有图标放大以填满模块。只保留帮助识别的图标，但也不能把承载实体差异的信息一并删除。

**留白分用途。** 模块内呼吸空间、层级分隔和路由走廊采用各自的尺度；不规定统一空白百分比，也不以铺满大背景容器计算密度。需要紧凑时缩短重复间隔、减少容器层数、重新分配栏宽；文字与必要机制优先保留。

**颜色形成系列。** 先从用户参考或既有图版选取适合的色相与中性色，再规定深浅角色。多类别任务保留必要类别色；强调程度可由着色面积与明度控制，不等于只能用一个颜色。设计时可用支持感知色彩空间的工具调色，交付时将色值落实为目标SVG渲染器兼容的显式颜色，不依赖某个CSS函数或配色服务。

**小尺度先于特效。** 查看实际栏宽的彩色与灰度预览，再看放大局部。若主要差异只有放大才看得出，优先改善层级、标签与形状。阴影、渐变或纹理只有在表达材料、层次等真实信息且通过输出兼容性验证时使用。

## 组合内容居中

每个元素框都检查水平与垂直两个方向。框中只有文字、图标或其他单元素时，居中该元素；有多个文本、图标或机制图元时，先排好内部顺序、行列和间距，再把整组可见内容居中。不能把每个成员都放在框中心，也不能只居中图标而让文字占据额外一侧。

- **先定内容区。** 普通节点使用边框内扣对称内边距的区域；带标题栏的分区分别定义标题区与主体区，标题相对标题区居中，主体图文组合相对主体区居中。预留的说明带、端口或布线走廊在布局说明中提前分配，不能事后挪动内容区来掩盖偏移。
- **量组合边界。** 以可见文字、图标及内部机制的联合包围盒计算中心，排除容器背景、透明占位框和外接连线。图标原始viewBox的空白、多行文本的行高框都不能替代可见内容范围。计算方法见 [SVG 与导出规范](svg-and-export.md#连线与边界)。
- **保留内部结构。** 图标在左、文字在右时，共用一条垂直中线并把左右组合作为整体水平居中；图标在上、文字在下时，共用水平中心线并把上下组合作为整体垂直居中。多行文字统一行距；内部确需左对齐的标签可保留，但整个文本块仍须在所属组合中居中。数据图的坐标位置、机制连线和矩阵内部排列不能因居中而改变科学含义。
- **逐框验收。** 比较内容中心与所属区域中心，并查看上下、左右留白。先消除测量偏差，再按实际字形与图标轮廓复查视觉居中；明显偏移不能以“光学修正”解释。测量容差按输出尺度声明，只用于渲染舍入，不是允许任意偏移。
- **居中不等于填满。** 内容放不下时重排、调整框尺寸或精简表达，不能靠裁切、缩小个别文字或取消必要间距来通过检查。紧凑机制图同样执行居中；宏观分区中的各行列作为整体居中，同时保持公共对齐线与路由空间。

边界包含检查与居中检查分别记录。“内容没有越框”不代表“内容已经居中”。字体、图标、文字行数或框尺寸发生变化后，重新测量并渲染。

## 有针对性地探索变体

用户已给出明确参考时，先深化其规律。方向不明确或首次改进效果难以判断时，可用同一科学内容做2–3个小样：例如“中性分区+核心强调”“分类色标题带+白色内容区”“较紧凑的图文分栏”。每个变体改变一个主要假设；区别应来自层级、密度或图文组织，而不只是换色。

统一比较比例、输出尺寸与文字内容；结构变化时说明布局差异，核对节点、边和语义没有丢失。先选择解释力更强的方向，再精修。不为每次文字修改强制生成三个方案，也不将所有探索稿称作最终成果。

## 设计评审与停止条件

在几何检查之外，按五个维度记录可见证据：

| 维度 | 判断问题 |
| --- | --- |
| 语义与功能 | 图形是否准确表达源材料？每个元素是否帮助识别、解释或导航？ |
| 视觉层级 | 是否有明确入口和阅读顺序？框、字、图标是否争抢注意力？ |
| 细节执行 | 基线、轮廓、间距、换行、箭头与光学居中是否协调？ |
| 系统一致性 | 配色、边框、字体和图形语法是否遵循既定角色？ |
| 方法辨识度 | 去掉标题后，是否还能看出本方法的结构特点，而非任意系统都可套用？ |

输出“保留 / 问题 / 修复 / 复查证据”。问题分为阻断理解或输出、影响层级与做工、可选微调；先处理前两类。需要评分时逐项给理由，不把自评分当作客观认证，不要求为了“创新”偏离论文表达习惯。

遇到“缺少质感”反馈，至少说明一个结构或层级层面的改变、一个图文细节层面的改变，并用同尺度前后图核对。若问题只涉及某个明确局部，可限定修改范围并说明原因。存在已知语义错误、缺字、碰撞或层级问题时继续修复；可见问题已解决时停止，不为了轮数继续增加装饰。
