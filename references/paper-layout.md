# 规整版式与视觉设计

论文框架图应像一个经过排版的完整图版：外轮廓规整，分区相互对齐，内部结构紧凑，读者能迅速辨认整体组织。方正指这种矩形秩序，不限定1:1画幅，也不要求直角边框。

网格之外的层级、视觉重量、字体、图标与评审方法见 [视觉层级与细节设计](visual-craft.md)。同高分栏可以采用不同内部表达；不要让统一容器样式掩盖方法重点。

## 从参考图提取什么

用户提供样例时，先观察以下四个层次，再将适用的规律写进绘图说明：

1. **骨架**：横向分栏、纵向分行、窄侧栏加主区，还是主区加共享辅助带。
2. **对齐**：哪些分区共用顶边、底边、标题基线；哪些内部模块共用行高或列边。
3. **密度**：每个分区如何容纳必要机制，窄区与宽区如何分工，长线使用哪些固定走廊。
4. **图文关系**：图标与短标签如何配对，内部小图如何替代长解释，颜色和边框在哪一级表达分组。

只迁移适合当前图的设计规律。样例中的方法、数值和模块不是当前论文的事实；其重阴影、高饱和底色或大标题也不自动成为默认风格。继续遵守用户要求的少量文字、低饱和色和可编辑SVG。

## 优先使用的矩形骨架

| 骨架 | 适用内容 | 排版要点 |
| --- | --- | --- |
| 窄输入栏 + 多个阶段栏 + 窄输出栏 | 输入/处理/结果明确的方法 | 中部阶段共用顶底边；输入输出更窄，图元列内对齐 |
| 同高角色栏 + 底部共享带 | 多角色代理、共享上下文或记忆 | 主栏等高，内部内容可不同；共享带与其服务的主区边界对齐 |
| 一排机制面板 | 各阶段都有内部算法或局部流程 | 各面板共用外边线，标题统一置顶或置底；面板内采用独立子网格 |
| 左侧分类栏 + 右侧多行内容 | 研究框架、分析维度、训练/推理分层 | 每行左右配对，分类栏宽度一致，主区左右边贯通，各行高度按内容分配 |

先选一个主骨架，需要时在某个分区内组合其他骨架。不要为满足示例骨架增加不存在的阶段或共享关系。

画幅按所选骨架、信息量和论文栏宽推导。横向多阶段图通常先尝试宽矩形；多层分析图可采用更接近常规页面图版的比例。不能为了“方正”强行做成正方形，也不能为压低高度而牺牲最终字号。

## 外层对齐，内层按内容组织

- 同一排的主要阶段容器默认共用顶边和底边；同一列默认共用左右边。内容多的区可以更宽，不必打破整排高度。
- 不同阶段可使用不同内部结构：图标列表、并行双列、局部循环、特征图或结果集合。内部自由变化应留在共同外框内。
- 所有同级标题选择相同位置、字号和基线。确需标题带时统一高度；标题与内容之间的分隔线统一起止位置。不要在同一层随意混用框内顶题、悬浮标题和框外底题。
- 共享记忆、验证、结果等辅助内容优先落在对齐的辅助行或侧栏中。辅助带可以缩短，但应对齐它服务的主区，避免成为无归属的浮动卡片。
- 空间对齐不等于逻辑归属。互不隶属的模块可以排在同一条辅助行，用间距建立秩序，不必添加会误导读者的共同系统边框。
- 允许有意义的例外，例如独立图例或少量输入符号；在说明中解释。不能让少数例外把主要视觉轮廓变成阶梯状或不规则散点。

### 将对齐写成可计算的约束

绘制前记录：外层四边、列宽、列间距、主区共同高度、标题带、辅助行高度、路由带，以及内部间距单位。例如，宽1600的横向图可以先确定：

`32 + 180 + 4×24 + 380 + 340 + 360 + 180 + 32 = 1600`

这里两侧各32为边距，两端180为窄输入/输出栏，中间380/340/360为三个主栏，四个间隔各24。各栏共用顶底坐标，内部按需要分行。数值仅示范宽度核算，不是要求所有框架采用五栏。

若24单位通道放不下箭头和标签，应重新分配列宽或通道，而不是压缩标签。高度也要满足“上下边距 + 主区 + 辅助/路由带”的核算，不能只规定宽度比例。

## 紧凑与留白

紧凑表示空间有用途，不表示把所有空隙填满。

- 区分外边距、模块内边距、结构分隔和连线通道。相同用途采用同一组尺度，例如基于一个间距单位选择1倍、2倍或3倍间隔，避免大量互不相关的微调值。
- 大块空白必须能说明用途：分开层级、容纳路由或保护阅读焦点。因某一模块偏短而留下的巨大空区，应先通过内部重排、分配列宽或组织辅助内容解决。
- 不能用放大图标、拉长箭头、增加装饰文字或复制模块填空。简单模块可以使用图标加短标签的紧凑单元，无需包成大卡片。
- 空间不足时，优先精简重复信息、调整内部排列、扩大需要细节的主栏，或拆出必要的局部面板。空间过剩时，优先收紧行列与画幅，而不是任意增大所有元素。
- 不设置统一的“填满百分比”。背景容器覆盖面积不能代表信息密度；应检查实际图文单元和连接通道的分布。

## 让连线服从图版骨架

先在规整骨架内安排局部线路，再将跨区关系安排在预留的行间、列间或外围窄带。

- 邻接阶段之间优先短连接，端口尽量落在对应行上，减少无意义的多次折返。
- 跨多个阶段的依赖可以沿顶部或底部共用走廊分层布线，但只有语义相同的关系才可以合并为总线。
- 长回路优先返回邻近且正确的端口。为一条回路扩大整张图、制造大块空白或绕过半张图时，应重新检查模块位置和路由带分配。
- 外围线路属于图版占位范围，必须计入最终边界。不能只把容器排成矩形，却让箭头和标签远远伸出去。
- 保持数据与控制关系准确。不能为了整齐而删边、改方向、改变模块归属或合并独立信号。

## 图标、文字与视觉重量

- 同级图标使用接近的视觉尺寸和描边重量；图标与标签的距离、对齐方向保持一致。
- 每个分区突出与阅读任务相关的信息。解释机制时展开必要内部关系；并列比较时突出对应项与差异，不要求添加内部机制。短操作可直接配图标，模块定义交给正文。
- 低饱和色优先用于阶段背景、关键模块或局部符号。可让同一阶段的图标和边框共享强调色，正文保持深色。
- 外层分组、内部模块和辅助轮廓使用有限的线宽层级。虚线边框必须具有明确分组含义；不要为每个小图元再套边框。
- 深色底、大面积重边框和阴影会增加视觉重量，仅在用户明确需要或信息层级确有必要时使用。论文图默认以清晰的图元和网格建立层级。

## 版式验收

在线框阶段和最终阶段各检查一次：

1. 缩小查看整图，主要图文与连接是否形成完整、均衡的矩形图版，而不是散落节点。
2. 同排主分区的顶底、同列的左右、同级标题的基线是否一致；例外是否有内容依据。
3. 主区和辅助区能否一眼辨认；是否有孤立的大卡片、意外空洞或一侧过重的情况。
4. 必要机制是否获得足够空间，简单输入输出是否占用过多面积；相近功能单元的密度是否协调。
5. 路由带是否紧凑且足以容纳线和标签；是否存在可以通过邻接重排缩短的长回路。
6. 同级图标、文字、边框和间距是否协调；最终论文尺寸下仍可辨认内部机制。

这些是设计判断，不能用“无碰撞”“外框面积大”或单一对齐分数替代。发现结构松散时回到分区布局修改，不应只继续修线和调整几个像素。
