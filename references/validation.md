# 验证与可移植性

设计要求独立于工具实现。完整完成一次绘图需要具备SVG编写、渲染、检查及所需格式导出能力；不要求特定操作系统、宿主应用或浏览器品牌。随附脚本各自有公开依赖，缺失时选择已有替代工具，不能将“可选”理解为脚本本身不需要其依赖。

## 包与路径边界

维护包包括 `SKILL.md`、`references/`、`scripts/`、`icons/`、`tests/`、README及许可证。随附脚本作为一个目录一起复制，Node适配器会引用同目录的 `node_support.cjs`。`tmp/`是本地试验输出，不是运行前提，也不应混入发布包。

用户项目图标优先；skill自带图标为后备。生成脚本可以读取原图标，但最终SVG必须内嵌图元。将成图单独复制到无图标目录后仍应可渲染。保留可编辑文本时，目标环境仍需要可用的相应文字字形；需要精确外观时按字体许可证处理嵌入或提供文字转路径副本，并保留可编辑主文件。

## 分层回归

从skill根目录运行以下命令；输出目录必须不存在或为空。脚本只使用临时副本，不安装软件、不改变全局配置、不读取既有试画输出。

```bash
python3 tests/validate_portability.py --work-dir tmp/validation
```

Python 3.9+即可检查文档链接、相对路径、结构检查器、文档生成示例和复杂框架生成。找到Node时还会检查CLI、源码语法、项目依赖解析和输入保护。可选集成依赖未提供时明确记为 `skip`；跳过不是通过。

已有Sharp、Playwright和兼容浏览器时，显式传入实际发现的位置：

```bash
python3 tests/validate_portability.py --work-dir tmp/validation-full \
  --node /path/to/node \
  --node-modules /path/to/node_modules \
  --browser /path/to/installed/browser
```

以上是POSIX shell语法，其他shell使用对应换行规则或单行调用。路径由调用者提供，不把示意路径复制进脚本或要求固定安装位置。

回归将包复制到含空格和中文的路径，从另一个工作目录调用，并清除继承的 `NODE_PATH` 和 `FIGURE_*`。覆盖输入覆盖保护（含文件别名）、无依赖错误、有效/异常XML、引用、CSS需复查状态、命名空间、非零viewBox原点、PNG物理宽度以及真实浏览器的导出与测量状态。结果写入 `validation.json`，记录实际系统、版本和逐项状态。若文件系统不支持链接或创建链接权限不足，对应链接用例应记录跳过及原因，不能假称已验证。

迁移目录测试不等于操作系统兼容性证明。声明支持其他系统前，在目标系统运行相同回归；另记录实际字体与渲染器。当前测试不验证任意SVG特性、不保证像素级跨系统一致，也不能证明科学内容正确或设计美观。

## 复杂框架实绘

先按绘图说明明确比例、同高分区、标题带、子网格、路由、字体、图标语义和关系。测试程序只生成一个假想用例，包含11个节点、12条边、并行编码、融合、状态读写及条件反馈，不作为通用布局模板。

```bash
python3 tests/build_framework_fixture.py --output-dir tmp/framework-check --wireframe
# 渲染并查看线框，必要时调整布局，再生成细化版。
python3 tests/build_framework_fixture.py --output-dir tmp/framework-check
python3 scripts/check_svg.py tmp/framework-check/framework.svg
```

再依照 [工具链用法](toolchain.md) 实际渲染、导出、读取测量报告，并逐项核对 `graph.json` 与SVG路径及父子分组。修改后重导出。分别记录结构、模块内边距、路径避障、整体版式、论文尺度与PDF复查结果；命令退出0仅代表相应工具的覆盖范围。

至少查看整图、局部与缩小灰度图，并将PDF重新渲染检查。导出后将SVG单独复制到无项目资源的目录再渲染。没有执行视觉复查时，不宣称复杂框架通过实绘验收。

## 视觉设计能力回归

### 高密度复杂图版实绘

依据 [高密度复杂图版设计](dense-mechanisms.md)，选择能覆盖本次变化的内容与关系形态开展实绘。效果参考不决定测试的学科内容或固定骨架；通用性检查应覆盖不同关系组织方式，不能仅替换同一模板中的术语。

下列现有多模态机制图是一个固定的维护用例，用于复现几何、导出与局部机制检查。它不是绘图起点、用户任务的默认模板或通用能力的完整证明；仅在其覆盖范围与本次验证相关时运行。新增其他用例时，从独立内容需求确定实体、布局和参数。

```bash
python3 tests/build_dense_framework_fixture.py --output-dir tmp/dense-framework-check
python3 scripts/check_svg.py tmp/dense-framework-check/framework.svg
```

该假想用例包含48个表示/计算单元、42条绘制关系与13项具名引用，覆盖共享特征、三尺度重复机制、前向/反向细化和训练损失。这些数量是本测试的记录，不是所有论文的要求，也不是质量评分。矩阵格子不计为独立单元。生成后仍须实际渲染、逐边核对、检查共享引用语义与最终尺寸。

用工具链中的 `export_browser.cjs` 测量该样例，输出目录设为样例的 `qa/`，宽180mm、`--padding 0`。随后运行 `python3 tests/center_dense_framework_fixture.py tmp/dense-framework-check`，按新鲜测量整体居中节点内容与56单位标题区；此适配器只处理该样例的坐标约定。再次渲染与测量后运行 `python3 tests/check_dense_framework_fixture.py tmp/dense-framework-check`，检查实际路径、端口、文字、节点归属及48组内容和6处标题的双轴中心。中心误差容差0.1个根SVG单位，用于舍入。字体包围盒只是可见字形的近似，仍须视觉复查；该脚本不自动测量宏观面板主体网格的居中程度。

提供真实浏览器依赖时，完整迁移回归也执行上述“渲染—居中—复测—关系检查”流程，并验证修改SVG后旧测量报告被拒绝。自动流程仍不能代替查看图像，也不替代不同关系形态的通用性实绘。

部分张量和圆形算子使用透明矩形作测量包围框；它不代表实际接口。边界检查需以可见图元及所声明端口为准。全图零内边距测量只检查包围框是否溢出，不能冒充节点文字留白验收；另查文字与算子边界、图元说明与父区、所有路径及标题。网格内部的有意相交与不相关节点/文字碰撞分别处理。

### 同尺度视觉对照

修改设计指导时，按 [视觉层级与细节设计](visual-craft.md) 做有针对性的前后对照：先记录原图的层级或做工问题，保留同一内容与比较尺度，再验证改动是否改善核心机制的识别、边框重量、图标体量或文字节奏。涉及结构调整时同时核对节点与关系。对需要多类别色的图保留分类编码，不将某个单色小样推广成唯一风格。

把语义功能、视觉层级、细节执行、系统一致性、方法辨识度分别记录为观察与修复证据。自动脚本通过、自己给出高分或把边框变细，均不能代替真实查看与设计判断。试验产物仍保存在临时目录，生产规则不引用试验路径或其他skill的安装位置。
